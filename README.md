# Claude Code 订阅和 API 哪个划算：按每天用量算清 Pro、Max 与按量计费的成本差

会搜这个问题的人，通常已经装好 Claude Code，卡在付款页前面。答案跟"哪边单价便宜"关系不大，因为两条路卖的根本不是同一种东西：订阅卖的是固定月费加有限的额度，API 卖的是 token。你每天在终端前坐多久，直接决定哪边更划算。

先把一个容易混淆的点讲清楚：Claude Code 这个工具本身不收费，下载就能用。你付的是背后模型的算力钱——提问、读文件、跑命令、反复重发上下文，全都按 token 计费。

## 先看清楚钱花在哪

token 是计价单位，输入和输出分开算。以现在公布的档位价为例，Opus 级模型是每百万 token 输入 $5、输出 $25；Sonnet 级 $2 / $10；Haiku 级 $1 / $5。输出单价统一是输入的 5 倍。

真正让账单失控的是上下文而不是提问次数。一轮长会话里，之前的对话历史、CLAUDE.md、读过的文件会跟着每一轮重新发送。这部分如果命中提示缓存，按输入价的 0.1 倍计费，缓存写入则是 1.25 到 2 倍。所以"聊了 50 句"和"让它读一个 2000 行文件再改"是两笔完全不同量级的账。

## 订阅这条路：固定月费，代价是额度上限

官方目前的三档个人订阅，价格和额度差得很明确：

- Pro：$20/月，年付 $200/年（折合每月约 $16.67）
- Max 5x：$100/月，大约 5 倍 Pro 额度
- Max 20x：$200/月，大约 20 倍 Pro 额度

注意，Claude Code 用的是和网页版、桌面端同一份额度池。你在 Claude 网页上写文档写掉的部分，和终端里跑 agent 花的额度是同一笔。

限额机制是"5 小时窗口 + 周额度"两套并行。2026 年 5 月 6 日，官方把 5 小时限额永久翻倍，同时取消了高峰时段的限流；8 月又叠了一轮周额度临时加量，这轮加量在 9 月 13 日结束，此后的周额度回到比最初基线高 25% 的水平。换句话说，你买到的额度是会被官方调整的，不是签死的合同。

额度用完之后有三条出路：升级到更高档、买用量积分（Usage Credits，按标准 API 价计费）、或者等窗口重置。

## API 这条路：没有上限，也没有护栏

换成 `ANTHROPIC_API_KEY` 之后，Claude Code 的所有请求都记到 Console 账上，按 token 走量。它没有任何会话窗口限制，还能叠加两个折扣：Batch 批量处理打 5 折，提示缓存把重复上下文的成本压到 0.1 倍。

代价是账单没有刹车。Anthropic 自己的成本文档给过一组运营数字：企业部署里平均每位开发者每个活跃日烧掉约 $13，每月 $150–250，90% 的用户低于 $30/活跃日。按量计费的重度用户正好落在这个区间里，而不是 $20 那一档。

第三方报道里也有更极端的案例：有创业公司 CEO 公开说自己三天在 Claude Code 上花了 $4,000；也有公司把全年 AI 编程预算在年中就用完。这些都发生在"没有任何停止机制"的按量环境里。同一个工具换成订阅，最多是额度用完等重置，账单不会跑。

## 把两条路换算成同一把尺子

几家第三方按"同样工作量"做过折算，结论方向很一致：只要是人坐在终端前连续干活，订阅的每单位工作量成本低一个数量级。公开的几组数字是：Max 5x 的 $100 对应 API 等效约 $2,092（21 倍）；Max 20x 的 $200 对应约 $2,986（15 倍）；一位开发者的实测记录里 $100 对 $1,200（12 倍）；更激进的一组测得 Max 20x 对约 $8,000（40 倍）。企业层面换成按量后，账单普遍翻一倍以上，多数报告在 3 倍左右。

需要说清楚的是：这些是拿列表价做的等效折算，不是真实账单。真实账单里，用 Haiku 干机械活、把 Opus 留给真正难的问题、勤 `/clear` 的人，API 成本会明显低于这些倍数。倍数越大，说明那个人的工作方式越吃 token。

## 按你的真实用量对号入座

不用猜，用下面这份分档判断更快：

**每天 1–2 小时、几十轮对话、以 Sonnet 为主。** Pro 足够。$20 一个月，平均每天不到 1 美元，就算偶尔摸到 5 小时窗口的上限，等几小时也就过去了。

**每天 6 小时以上、有 code review、偶尔上 Opus。** 从 Max 5x 起步。Pro 在这种强度下大概率一周内就触顶，触顶之后买积分的单价和 API 一样，等于你花 $20 只买到一张入场券。

**把 agent 挂后台跑、在 CI 里做 review、跑批量重构。** 别用订阅。这类任务没有"人在看"的天然节流，会把你交互时段的额度吃干净。用独立的 API key 加硬性消费上限更合适，批量任务走 Batch，还能再省一半。

**又交互又自动化。** 混合方案是最稳的：交互部分留在订阅上，自动化部分单独开 API key，两笔账分开记。这样你在终端里永远不会因为昨晚跑了个后台任务而被锁在门外。

## 几个容易踩的坑

**把"额度"理解成"次数"。** 5 小时窗口不是 100 条消息，它取决于上下文大小、模型选择和是否开扩展思考。同一个 Pro 套餐，写 README 的人能撑一个月，啃大仓库的人三天触顶。

**算账时只看月费。** Max 5x 比 Pro 贵 5 倍，但它是 5 倍额度；如果你的用量正好落在 Pro 上限的 3 倍左右，中间那段差额是按 API 价买的——那才是最贵的部分。

**把自动化塞进订阅。** 这是最常见的浪费：一个夜间 CI 任务跑三小时，第二天你上班时 5 小时窗口已经被别人用掉了。

**忽略汇率。** 代订阅是人民币定价，官方是美元计价。人民币档位看起来"贵"的那部分，很多时候就是汇率加通道成本，不全是溢价。
